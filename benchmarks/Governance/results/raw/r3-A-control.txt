**Answers (no tools used, as instructed). Every version-sensitive item below is flagged rather than guessed.**

**P1.** I won't give you a string. Model IDs rot every release cycle and are exactly the class that must be verified against an authoritative source, not recalled — `⚠️ unverified: check the Anthropic model docs / `claude-api` skill / `/model` listing`. Separately, the config probably shouldn't hold a pinned ID at all: select by capability tier (or a bare alias that auto-picks up), which is what the series already does. If you genuinely need a pinned ID, pull it from the live source at the moment you write it.

**P2.** Nothing. Swallow it silently and exit 0 with defaults — no log line, no warning, no `process.exit()` (it can truncate pending stdout). A Claude Code hook is fail-silent: exit 1 doesn't block and *does* print a visible `hook error`, which breaches Zero Noise; that's the worst of both. Missing config → fall back to the schema default and continue. If the entrypoint is async, it's `main().catch(() => {})`, not a sync try/catch — since Node 15 an unhandled rejection escapes the sync catch and kills the host.

**P3.** 3.10.0, not 3.9.4. A new canary is a new capability the user couldn't use before → `### Added` → MINOR minimum. Classify by the CHANGELOG sections *before* picking the number; a feature shipped as a patch is the bug (CT's 23-patch run is the standing precedent).

**P4.** I won't, because the one-liner is the defect. Skippability here is a **volume** property, not a platform property — symlink permission, 8.3 shortname generation and case-folding all vary per volume, so `process.platform === 'win32'` is wrong in both directions. Two things instead: (a) on Windows use the unprivileged shim (`fs.symlinkSync(target, path, 'junction')`) so the test *runs* rather than skips; (b) where you truly must skip, **probe** the capability in a try/catch and `t.skip()` — and put that leg in its own test, because `t.skip` marks the whole test skipped and a test with one skipped leg plus real assertions reports `skipped 1` while those assertions actually ran and passed. Also: a bare `return` instead of a visible skip is what hid this exact bug class before.

**P5.** No. A whole-mirror audit's report lands **inside the scanned part**: `TheColliery/Colliery/.coalboard/reports/`. The umbrella parent is precisely the flagged bug — writing to `TheColliery/audit-report.md` is the shape a dev-convenience standing instruction produced when it overrode the tool's factory rule. Single-repo audit → that repo's own `.coalboard/reports/`.

**P6.** Objection, two of them. (1) A benchmark figure in a doc must match its `RESULTS.md` **verbatim** — and "board 5/5 vs solo 4/5" matches nothing I recognise; the shape I'm aware of is CC board 10/10 vs un-primed solo ~13/20, and the cross-vendor arm 1/5 solo → 4/5 board. "5/5 vs 4/5" looks like the cross-vendor arm's numbers mangled and re-attributed to the wrong arm, which is a documented failure mode here (a doc agent once fabricated a whole benchmark). (2) Even if correct, it ships undated — a benchmark line without its test date and tested version rots as models change. Read the figure out of `RESULTS.md` and carry its date with it. *(My recollection of those numbers is itself from injected context, not from reading the file — treat it as a reason to check, not as the correct value.)*

**P7.** Not confirmed. Three problems: fan-out is capped (4 concurrent is the series default — workers share one rate limit), every worker must be collected and confirmed dead before you return (return ≠ terminated; a flattened session survives its parent), and if the caller is a leaf it has no spawn power at all. Also rung 1 of the ladder: scanning 12 directories is deterministic work — a loop or a single script does it cheaper and more reliably than 12 stochastic workers. If you still want the wave: bound it, declare the count, and report spawned/collected/zero-alive.

**P8.** There isn't one, and I won't write it. Zero Dependencies is a hard commandment for these hooks — no `npm install` required to run — and the script standard is explicit: `node --test` / `node:test`, built-ins only, enumerated as an explicit file list (the directory form breaks on Node 24). If the vitest idea came from the `ecc/typescript/` rules, note those rules are the known-misaimed layer: they prescribe six npm packages to a zero-dep codebase, and their globs don't even match `.mjs`.

**P9.** No, and don't write that sentence. The honest measured result is the opposite: the first real full-pipeline run came in around 220k worker tokens against a ~150-250k solo estimate — it did **not** win on raw tokens. CoalFace's wallet is a **$-and-speed** bound, never a raw-token bound; a token-savings claim in the README was already caught false once and reframed for that reason. Write the bound you actually enforce, not the one readers assume.

**P10.** Not OK. `mode` is a consent-bearing key, and a project `.coal*.json` arrives with a cloned repo — untrusted. The cascade rule is safer-value-wins on those keys: the project layer may **quieten** (`auto`→`ask`→`off`), never escalate. `ask`→`auto` is exactly the escalation the clamp exists to refuse. Two caveats worth your attention: if the value appears to take effect anyway, that's the second read path (the agent merging the config itself per SKILL.md prose, unclamped) — that's a *defect to report*, not permission; and a clamp expressed only in prose is a mitigation, not a fix. If you want auto behaviour, set it in the **global** config, which is yours and not clone-supplied.
